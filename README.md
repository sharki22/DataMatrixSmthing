## Лабораторная работа №1. Библиотека классов для Data Matrix

**Темы:** Классы, ассоциация (композиция, агрегация); поля, свойства и методы; статические поля, свойства и методы; операторы и перегрузка операторов; обработка строк и работа с массивами.
**Тип проекта:** Библиотека классов + Консольное приложение.
**Время:** 6 часов.

### Задание
Разработать библиотеку классов для работы со штрихкодами. Библиотека позволяет:
* Формировать двумерный матричный штрихкод (Data Matrix) на основе текстовой информации.
* Выводить информацию по Data Matrix.
* Кодировать текстовую информацию только в **ASCII режиме**.

**Запрещается** использовать обработку исключительных ситуаций и генерировать исключения.

### Техническое задание
#### Часть 1. Интерфейс Data Matrix
Интерфейс требует реализации следующего функционала:
* Общий способ формирования вывода Data Matrix или реализация по умолчанию.
* Получение информации по строке Data Matrix.
* Получение информации по тексту.
* Установка нового значения текста.

#### Часть 2. Класс Data Matrix
Описать в виде класса без виртуальных методов, реализующего интерфейс выше.
1. **Атрибуты класса:** заданный текст, версия Data Matrix, уровень коррекции, маска, строка кода в текстовом виде.
2. **Свойства:** Информацию по тексту можно изменять, при этом код обновляется автоматически. Изменять строку кода вне класса запрещено.
3. **Способ вывода:** задается статически для всех объектов (Только текст; Только код; Код + текст).
4. У класса нет конструкторов по умолчанию, с параметрами и конструктора копирования.
5. При создании объекта текст не передается (генерируется автоматически).
6. Класс не должен содержать дополнительных открытых методов и полей («Класс-Модель»), только геттеры и сеттеры.
7. Перегрузить `ToString()`.
8. Логика формирования Data Matrix должна быть в «Классе-Сервисе».

#### Части 3 и 4. Алгоритм формирования Data Matrix
* **Этап 1:** Преобразование ASCII строки в массив байт (числовые пары, спецсимволы).
* **Этап 2:** Определение размерности матрицы и блока данных, добавление кодов коррекции.
* **Этап 3:** Формирование кодов коррекции ошибок (по алгоритму Галуа).
* **Этап 4:** Размещение данных в матрице битов и преобразование в многострочную строку (символы `■` и пробел).
* **Вывод:** В зависимости от режима (Text, Code, Full).

## Лабораторная работа №2. Товары и Упаковки

**Темы:** Классы, наследование и ассоциация; поля, свойства и автосвойства; статические поля, свойства и методы; виртуальные методы и перегрузка методов, Ad-hoc-полиморфизм, интерфейсы.
**Тип проекта:** Библиотека классов.
**Время:** 4 часа.

### Задание
Создать библиотеку классов, подключить зависимость от ЛР1.
**Запрещается** использовать обработку исключительных ситуаций.

### Техническое задание
#### Часть 1. Класс кода упаковки
Добавить новый класс, реализующий интерфейс кода из ЛР1 (композиция, не наследование).
* Атрибут: Код из ЛР1.
* Перегрузить `ToString()` так, чтобы текст обрамлялся звездочками `* Текст *`.

#### Часть 2. Интерфейс товара
* Получение/установка идентификатора.
* Получение/установка цены.
* Получение наименования.
* Получение кода товара (через интерфейс из ЛР1).
* Получение типа товара.
* Получение дополнительной информации.

#### Часть 3. Абстрактный класс Товар
1. **Атрибуты:** Идентификатор (целое), Цена (подходящий тип для финансов).
2. **Функционал:** Виртуальные геттер/сеттер Id и Price, абстрактные геттеры типа и информации.
3. Один защищенный конструктор с параметрами.
4. Код (Data Matrix) должен обновляться при смене Id или Price. Запрещено создавать каждый раз новый экземпляр кода.
5. Текст кода связан с Id и Price: `$"{Id}:{Price}"`.
6. Перегрузить `ToString()` (нельзя перегружать в производных).
7. Класс не должен содержать открытых методов и полей (кроме `ToString()`), не знает о других классах.

**Производный класс:** Минимум 2 новых атрибута, перегрузка типа и информации. Использовать основной конструктор.

#### Часть 4. Класс Упаковки
* Производный от Товара.
* Поле: интерфейс товара.
* Конструктор принимает интерфейс товара.
* Цена = 110% от исходной, Id и Наименование совпадают.
* Свой код (из Части 1).
* Свойства ссылаются на товар (кроме цены). Перегрузить свойство "информация" и тип товара. `ToString()` не перегружать.

**Варианты товаров (1-42):** Вычислительные машины, Строительные материалы, Электроинструмент, Железнодорожный транспорт и др. (см. полный список в приложении 1).

## Лабораторная работа №3. Обобщенный склад (Витрина)

**Темы:** Обобщения (Generics), методы расширения, контейнеры.
**Тип проекта:** Библиотека классов.
**Время:** 4 часа.

### Техническое задание
Создать библиотеку классов, подключить зависимость от ЛР2.

#### Часть 1. Обобщенный интерфейс склада
* Получение/установка идентификатора склада.
* Получение размера.
* Индексатор для товара.
* Добавление в пустую ячейку / по индексу.
* Извлечение товара по индексу.
* Перестановка, замена.
* Поиск позиции (по Id и Наименованию).
* Сортировка (по Id и Наименованию).

#### Часть 2. Методы расширения товара
1. Установка текста кода товара на основе Id товара, Id склада и позиции: `$"{Идентификатор_склада}|[{Позиция_товара_на_складе}]:{Идентификатор_товара}:{цена_товара}"`.
2. Установка текста кода, зная склад (на котором он находится).
* Методы должны работать для любого товара из ЛР2.

#### Часть 3. Класс-контейнер Склад
1. Уникальный числовой код (идентификатор).
2. Взаимодействует с товарами через обобщение (любой товар реализует интерфейс товара из ЛР2).
3. **Только один защищенный конструктор**. Запрещено использовать синглтон, фабричные методы, рефлексию. Создание только внутри класса. При создании явно задается количество элементов (например, `Склад assortment = 10;` или `var v = (Склад)10;`).

#### Часть 4. Индексатор и методы
* Реализовать виртуальный индексатор `[]`. Снятие товара из ячейки (возврат не обязателен). Если места нет — вернуть `null` или `return`.
* Методы добавления, удаления, замены, перестановки.
* Поиск позиции по Id и Наименованию.
* Сортировка по Id и Наименованию.
* Перегрузить `ToString()` для вывода всех элементов, включая пустые ячейки.

#### Часть 5. Методы расширения для автоматического обновления кода
Использовать методы из Части 2, чтобы Data Matrix обновлялся при:
* изменении позиции товара;
* изменении идентификатора склада;
* перемещении товара на другой склад;
* код сбрасывается только при смене Id товара, но не трогается при удалении со склада.

#### Часть 6. Виртуальные члены
Сделать виртуальными: Свойство Id склада, Индексатор, Функции поиска и сортировки. Остальное перегружать нельзя.

## Лабораторная работа №4. Делегаты, События, IDisposable

**Темы:** Делегаты и события, аргументы событий, множественная реализация интерфейсов, интерфейс `IDisposable`.
**Тип проекта:** Консольное приложение.
**Время:** 4 часа.

### Задание
Разработать ПО для терминала формирования ассортимента (складирование). Автообновление Data Matrix/QR-кода при изменении Id товара, цены и Id склада.

### Техническое задание
#### Часть 1. Модификация склада из ЛР3
1. Создать новый **запакованный** (`sealed`) обобщенный класс склада.
2. Только один закрытый конструктор (размер, либо кортеж размер+Id).
3. **Делегат и событие смены Id склада:** Объявить атрибут типа делегат (лучше использовать готовые `Action`/`Func`/`EventHandler`). Параметр — текущий экземпляр склада.
4. Перегрузить свойство Id так, чтобы делегат вызывался только при изменении на новое значение и при наличии подписчиков.
5. Перегрузить индексатор, чтобы задействовать методы расширения товара из ЛР3 для подписки/отписки на смену Id склада. Складу не нужно обновлять код каждого товара, он делегирует это методу расширения.
6. Перегрузить две функции сортировки через новую функцию с использованием делегатов (вынести общую часть в закрытый метод, отличающуюся логику — в делегат). Для обновления кода товара использовать делегат смены Id.
7. Аналогично перегрузить функции поиска позиции товара через делегаты.

#### Часть 2. События товара и упаковки
1. Создать класс, производный от `EventArgs` (оканчивается на `Args`), с основным конструктором (новый Id и цена).
2. Создать новый интерфейс товара (производный от ЛР2).
   * Событие изменения данных: `EventHandler<T>` где `T` — класс из п.1.
3. Создать новый **запакованный** класс товара (производный от ЛР2). Перегрузить свойства Id и Price для вызова события.
4. Создать новый **запакованный** класс упаковки (производный от ЛР2, реализует новый интерфейс и `IDisposable`).
   * Только один конструктор (принимает новый интерфейс товара).
   * Подписывается на событие изменения данных товара.
   * При изменении Id/Price товара — обновляет свои данные (с наценкой 10%).
   * Информирует об изменении своих данных.
   * При освобождении памяти (`Dispose`) обязательно отписывается от события.
5. Модифицировать класс нового склада из Ч.1 для работы с новым интерфейсом товара (подписка/отписка на события для пересчета Data Matrix).
6. Реализовать `IDisposable` в классе склада для гарантированной отписки от событий товара и делегата смены Id склада.

**Тестирование:** Смотреть псевдокод в документе (создание склада, добавление товаров, изменение Id/Price и вывод).
